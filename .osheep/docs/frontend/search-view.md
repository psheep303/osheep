# 搜索面板

## 目标

在左侧栏提供一个接近 VS Code 的全工作区文本搜索体验：用户在搜索框输入关键词后，前端调用后端搜索接口扫描工作区内所有可读文本文件，并把匹配项分组渲染。点击单条结果可在编辑区打开对应文件并跳到匹配行。

---

## 入口

- 活动栏的"搜索"图标（已存在）
- 选中后左侧栏渲染本面板，与"资源管理器"互斥（活动栏负责切换）
- 再次点击活动栏可折叠左侧栏

---

## 布局

```
┌────────────────────────────────┐
│  搜索栏 + 修饰符按钮            │
│  替换栏（可折叠）+ 替换按钮      │
│  ▽ 包含 / 排除（可折叠）         │
│    include 模式                 │
│    exclude 模式                 │
│  统计行：N 个结果，M 个文件      │
├────────────────────────────────┤
│  结果树（可滚动）                │
│    ▼ relative/path/to/file.ts   │
│       12   ...match...          │
│       42   ...match...          │
│    ▼ other.md                   │
│       3    ...match...          │
└────────────────────────────────┘
```

### 搜索栏

- 单行输入，回车触发搜索
- 右侧排列三个修饰符按钮（与 VS Code 一致）：
  - `Aa` 区分大小写（Case sensitive）
  - `ab` 全词匹配（Whole word）
  - `.*` 正则模式（Regex）
- 修饰符按钮为切换态，激活时高亮
- 搜索框右侧另有一个 `≡` 展开按钮，点击后展开"替换栏"

### 替换栏

- 仅在用户主动展开后显示
- 单行输入框 + `替换全部` 按钮
- 替换全部触发后弹出二次确认（避免误操作）

### include / exclude

- 默认折叠为一行 `files to include / exclude`
- 展开后两个输入框：
  - include：glob 列表（逗号分隔），如 `src/**/*.ts, *.md`
  - exclude：glob 列表，叠加在后端默认忽略集合之上
- 后端默认忽略：`node_modules, .git, dist, build, .next, .vite, .cache`

### 结果树

- 一级条目：文件，显示相对路径、命中数
- 二级条目：行预览 `<line>  <text snippet>`，命中部分以高亮色（背景 + 加粗）渲染
- 点击文件名：折叠 / 展开
- 点击行：在中央编辑区打开该文件，光标移动到对应行（详见"与编辑器的联动"）
- 文件名右侧悬停出现 `×`：从结果列表移除该文件（不影响磁盘）
- 行右侧悬停出现 `×`：从结果列表移除该单条命中

### 空 / 加载 / 错误态

- 关键词为空时只显示提示文字
- 进行中：在统计行处显示 spinner + "搜索中…"
- 无结果：显示 `没有结果`，不渲染结果树
- 错误：在统计行下方显示一条红色 banner，可手动关闭

---

## 与编辑器的联动

- 点击单条命中：
  - 若该文件已在某个 Tab 打开，激活该 Tab 并把光标移到对应行 + 列
  - 若未打开，先调用后端读取，新建 Tab 后再跳转
  - 跳转目标行通过 [EditorPane](#) 暴露的 `goto(line, column)` 实现（基于 Monaco `revealLineInCenter` + `setPosition`）
- 文件被重命名 / 删除时（来自资源管理器的事件），搜索结果中对应条目同步更新或标记失效；当前阶段简化为：用户重新搜索即可，结果不实时跟踪文件树变更

## 数据流

```
SearchView
  └─ onSearch(query, options) ──▶ api.searchWorkspace(...)
                                    │
                                    ▼
                          后端 GET /api/workspaces/:id/search
                                    │
                                    ▼
                       响应：{ matches: [...], truncated }
```

请求参数与响应结构详见 [../backend/search-api.md](../backend/search-api.md)。

---

## 性能约束（当前阶段）

- 全文搜索由后端单次扫描完成，不做增量索引
- 单次扫描最大文件数 5000，超过则截断并把 `truncated: true` 返回
- 单文件最大 2 MB；超过的跳过
- 单个结果最多 200 个文件 × 每文件 100 行命中
- 后续阶段可以替换为 ripgrep 子进程，本面板无需改动

---

## UI 原则

1. 输入即焦点：打开面板时自动 focus 搜索框
2. 修饰符状态在面板内保留，但跨工作区不持久化（本阶段）
3. 行预览要够窄，左右溢出折断；右键复制文本由浏览器原生支持
4. 不抢编辑区视觉重心：结果树字号略小于编辑器
