# LLM Provider 抽象

## 目标

支持 osheep 在不改动上层流程的前提下切换不同模型提供方。

---

## 设计原则

1. 上层流程只关心能力，不关心具体厂商
2. Provider 必须支持流式输出
3. Provider 必须支持统一消息输入结构
4. Provider 配置应来自项目设置或服务端配置
5. 后续可扩展工具调用能力

---

## 最小能力接口

### chat
用于普通对话与文档修订

### generateStructured
用于生成结构化结果，例如：
- 文档摘要
- 待确认项
- Todo 列表

### stream
用于前端实时显示生成过程

---

## 当前阶段要求

- 先支持一个主力 Provider
- 保留扩展多个 Provider 的接口
- 不在业务流程中写死供应商逻辑
