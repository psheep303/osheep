# 部署与运行时

## 目标

使 osheep 能够长期在服务器运行，并保持尽量轻量。

---

## 当前阶段部署原则

1. 优先单机部署
2. 前后端服务分离但尽量简单
3. 异步任务独立 Worker
4. 使用 PostgreSQL 和 Redis 作为基础依赖
5. Docker 先用于执行环境准备，不急于上复杂编排

---

## 推荐部署组件

### Web 服务
- 提供前端页面
- 提供 HTTP API
- 提供 WebSocket

### Worker 服务
- 消费 BullMQ 任务
- 调用 LLM Provider
- 写回任务结果

### PostgreSQL
- 存储项目元数据
- 存储文档状态
- 存储 Todo 状态
- 存储任务记录

### Redis
- 作为 BullMQ 队列后端
- 作为轻量缓存

---

## 轻量化原则

1. 不提前引入 Kubernetes
2. 不提前拆过多微服务
3. 不提前做复杂多租户
4. 不提前接入过多模型供应商
5. 优先确保单项目流程稳定可跑通
