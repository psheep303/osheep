# MVP 计划：Web IDE 与生成流程

## 目标

实现 osheep 的第一阶段最小可用版本，使用户能够在浏览器中围绕一个项目完成以下流程：

1. 输入需求
2. AI 生成项目文档
3. 用户与 AI 对齐文档
4. 用户批准后 AI 生成 Todo
5. 用户批准后 AI 执行开发
6. 用户在前端查看日志、文件变更和任务状态

---

## 范围

### 本阶段包含
- 基于 Theia 的 Web 工作台
- 文件树、编辑器、终端、侧边栏
- 文档面板
- 需求输入与多轮对话
- AI 文档生成
- Todo 生成
- 执行入口
- 基础任务状态追踪

### 本阶段不包含
- 维护模式
- PR 审查
- Issue 审查
- 多用户协同
- 完整权限系统
- 复杂插件市场

---

## 里程碑

### M1：工作台骨架
- 能在浏览器中打开项目
- 能查看和编辑文件
- 能显示 `.osheep` 文档
- 能显示 AI 面板与任务面板

### M2：文档生成流程
- 用户输入需求
- AI 生成初始文档
- 文档写入 `.osheep`
- 用户可通过聊天和手动编辑进行修订

### M3：Todo 生成流程
- 文档达到确认状态
- 用户点击批准
- AI 生成结构化 Todo
- Todo 可展示、可确认、可重新生成

### M4：执行流程
- 用户批准 Todo
- AI 进入执行阶段
- 展示执行日志、任务状态、文件变更
- 支持中断与重试

---

## 验收标准

### 产品验收
- 用户能够完整走通一次“需求 → 文档 → Todo → 执行”
- 文档流转状态清晰
- Todo 状态清晰
- 前端能稳定展示任务过程

### 技术验收
- 前后端职责清晰
- AI 调用可替换 Provider
- 任务执行异步化
- 项目文档固定落地到 `.osheep`

---

## 优先级

### P0
- 工作台基础布局
- 文档生成
- 文档确认
- Todo 生成
- 执行入口

### P1
- 日志回放
- diff 展示
- 任务中断
- 历史版本切换

### P2
- 文档模板
- 多 Provider 策略
- 更细粒度的审批流
