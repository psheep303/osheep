# osheep basic

## 简介

osheep basic 是一个基础的 AI 编程工作流。用户输入开发任务后，由 Codex 执行任务并运行测试；测试通过后可输入 Commit 消息提交代码，测试失败时则进入修正流程，修正完成后重新执行任务。

该工作流适合用于日常代码修改、测试验证和可选的 Git 提交。

## 工作流程

```text
启动工作流
↓
设置输入任务
↓
Codex 执行任务
↓
运行测试
↓
人工查看执行摘要
├─ 测试通过 → 输入 Commit 消息
│                ↓
│             条件判断
│                └─ 消息不为空 → Git Commit
│
└─ 测试失败 → 修正问题
                    ↓
                条件判断
                    └─ 修正内容不为空
                        ↓
                    更新任务变量
                        ↓
                    Codex 重新执行
```

## 节点说明

### Workflow run

工作流触发节点，负责启动工作流。

### 输入任务

**类型：** `variable`

**变量配置：**

```text
input = ""
```

用于保存用户输入的开发任务。

### Codex

**类型：** `agent`

**提示词：**

```text
{{vars[input]}}
```

Codex 使用 input 变量中的任务描述执行代码修改或其他开发工作。

**主要配置：**

* 模型：default
* 思考强度：high
* 最大重试次数：5
* 重试间隔：20 秒
* 重试策略：lowest-multiplier
* 备用 Provider：sas
* 自动成功：启用
* 中断后继续运行：启用

### 运行测试

**类型：** `command`

用于运行项目测试，并将测试结果传递给后续节点。

当前工作流数据中未记录具体的测试命令，需要在工作流编辑器中确认或补充。

### 查看摘要

**类型：** `markdown`

**内容：**

```text
{{blocks[2].text}}
```

用于展示 Codex 的执行摘要，并等待人工审批。

**审批结果：**

* 成功：进入 Commit 流程。
* 失败：进入修正流程。

### commit消息

**类型：** `input`

**输入标题：**

```text
commit text?  (留空拒绝)
```

用于输入 Git Commit 消息。留空表示不提交代码。

### 条件判断：Commit

**判断表达式：**

```text
{{blocks[9].text}} != ""
```

当 Commit 消息不为空时，执行 Git Commit；为空时结束该分支。

### Commit 提交

**类型：** `git-commit`

**提交消息：**

```text
{{blocks[9].text}}
```

**配置：**

```json
{
  "stageAll": true
}
```

执行提交时会自动暂存所有变更文件。

### 修正

**类型：** `markdown`

**内容：**

```text
{{blocks[2].text}}
```

用于展示失败结果，并将其作为后续修正任务的依据。

### 条件判断：修正

**判断表达式：**

```text
{{blocks[15].text}} != ""
```

当修正内容不为空时，进入环境变量节点；为空时结束修正流程。

### 环境变量

**类型：** `variable`

**变量配置：**

```text
input = {{blocks[15].text}}
```

将修正内容写回 input 变量，然后重新执行 Codex。

## 变量引用

| 引用                    | 说明         |
| --------------------- | ---------- |
| `{{vars[input]}}`     | 当前输入任务     |
| `{{blocks[2].text}}`  | Codex 执行摘要 |
| `{{blocks[9].text}}`  | Commit 消息  |
| `{{blocks[15].text}}` | 修正内容       |

## 注意事项

* 运行测试 节点当前未显示具体命令，需要确认其实际配置。
* 修改节点编号后，需要同步更新所有 `blocks[n]` 引用。
* `stageAll: true` 会将工作区中的所有变更加入 Commit。
* Commit 消息为空时不会提交代码。
* 修正内容为空时不会重新执行 Codex。
